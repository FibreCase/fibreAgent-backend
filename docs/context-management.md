# 上下文管理

在「最近 N 条消息」的窗口之上，再加一道**保守、模型无关的估算 token 预算**，这样一条很长的消息或很多张图都不会把任何 OpenAI 兼容端点的真实上下文窗口撑爆。核心逻辑集中在 `agent/context.py`，是**纯 Python**（无 Telegram / OpenAI SDK / SQLAlchemy / 文件系统 / `AttachmentStore`），只吃 role / 文本 / 附件**元数据**，**不含**任何图片字节。

## 估算器（不是计费 token）

一个确定、可单元测试的估算，用于**相对选择与保护**，**不是** provider 计费 token：

- **每条消息**先加一个信封 `MESSAGE_ENVELOPE_UNITS = 4`。
- 文本成本（`estimate_text_cost`）：
  - 每个 CJK（汉字/假名/谚文）codepoint 计 **1**；
  - 连续的 ASCII（字母/数字/空白/标点）按 `ceil(n/4)`（每 4 字符 1 单位，向上取整）；
  - 其它 Unicode（带重音拉丁、emoji、…）保守计**每个 1**；
  - 空 / `None` 计 0。
- 每个保留在 context 里的图片计 `CONTEXT_IMAGE_ESTIMATED_TOKENS`（默认 2000）。

`message_cost = 4 + 文本成本 + 图片数 × 图片成本`。

> 没有 `tiktoken`、没有模型专用 tokenizer、没有「模型名 → 上下文窗口」表、没有任何按模型名猜能力。若真实端点仍报上下文超长，走既有的安全 `http_error` 路径（不重试、不自动探测窗口）。

## 选取规则（`plan_context`）

系统提示**始终保留**；**当前用户请求始终保留、其图片从不降级**；历史按**完整对话 turn**（一条 `user` 消息 + 其后的 `assistant` 消息；异常行安全归组）**从新到旧**选取，使请求**同时**满足 `MAX_CONTEXT_MESSAGES` 与 token 预算：

1. 某个历史 turn 的**完整（含图）形态**放不下、但**纯文本形态**放得下 → **降级为纯文本**（它的图片被丢弃、**从不**从磁盘读取，但说明文字/回复保留）。
2. 纯文本形态也放不下 → **停**（**不**跳过去挑更旧的 turn）。
3. 输出按时间顺序，system 在最前。

**当前请求（含图）超预算** → 稳定的 `current_over_budget`，**不**调用 LLM（回一条「请缩短文字或减少图片」的安全提示）——用户的文字和已持久化的图片保留，与别的失败路径一致。

### 服务层如何驱动

`AgentService` 构建轻量的 `TurnCandidate`（role / 文本 / 消息 id / 附件**元数据**——**无字节**），调 planner，**只有**规划之后才重水化**被选中**的附件。降级/未选中的轮次按纯文本发出或省略；其 blob 永不读取。`/context` 命令用同样的 `plan_context`（空当前用户）做只读预览——只报计数/估算，**不读**任何附件 blob、**不泄露**任何文本/digest/路径。

## 配置项

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `MAX_CONTEXT_MESSAGES` | `50` | 携带的最近 N 条消息（消息数，非 token），另加一条 system。 |
| `MAX_CONTEXT_ESTIMATED_TOKENS` | `24000` | 一次请求（system + 选中历史 + 当前）的估算 token 预算。模型无关的保守估算，**不是**计费 token，与 `MAX_CONTEXT_MESSAGES` 共同约束。 |
| `CONTEXT_IMAGE_ESTIMATED_TOKENS` | `2000` | 估算中每张保留图片的成本，planner 用它判断某个历史 turn 的图放不放得下。 |

三者都按正整数（`>= 1`）校验。

## 限制

- **估算而非计费**：用于相对选择与保护，不等于准确 tokenization；超预算请求走 `http_error` 安全提示，本阶段不重试/不自动学习窗口。
- **turn 粒度，非 message 粒度**：完整对话 turn 一起保留；放不下的**最新** turn（即使纯文本也放不下）是硬停，planner 不越过它去拿更旧的。降级按 turn（一次性丢掉它的全部图片），非按图。
- **当前请求从不降级**：当前用户消息及其图片永远完整保留；只有**历史**图片可降级为文本。仅 system + 当前就超预算时，**拒绝**请求（不调 LLM）而非裁剪。
- **被丢弃历史不自动摘要**：超窗/超预算的历史只是从请求里省略（仍在 DB，用户可见）。无自动摘要——Phase-2.5 记忆是**独立、显式、用户保存**的事实库（见 [长期记忆](memory.md)），不是自动摘要。
- **不自动重试**：超预算请求回用户可读的 `context_limit`（或 `http_error`），后端绝不悄悄用更小上下文重试。
