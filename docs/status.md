# 当前开发状态

一个已在 Telegram 上跑通的最小个人 Agent backend：长轮询适配、渠道无关的核心服务、OpenAI 兼容 LLM 客户端、SQLite 持久化对话，外加**工具调用 + 工具安全**、**远程 MCP 工具（Streamable HTTP + stdio 本地进程）**、**只读基础设施观测（SSH）**、**图片输入/持久化**、**上下文预算管理**与**显式长期记忆**。当前能做的，以及有意不做的事，都收敛在这份文档里。

**能做的**
- **工具调用**：`agent/tool_loop.py` 在 `Agent Service` 与 `LLM Client` 之间循环执行工具——拿到模型返回的 `tool_calls` 就按名经 registry 执行、把 `tool` 结果回灌 messages，直到模型给出最终文本（或用尽 `MAX_TOOL_ITERATIONS`）。`tools/` 提供 `Tool` 接口 + `ToolRegistry`（注册 / 生成 OpenAI schema / 按名执行）+ 三个只读内置工具 + **两个可选状态变更本地能力**：`exec` shell 工具（`ENABLE_EXEC_TOOL=true` 才注册，恒 `ask`、静态 denylist 兜底）与 `file` 工具集（`ENABLE_FILE_TOOL=true` 才注册，九个 `file_*` 工具——`file_read` / `file_ls` 只读 `allow`、其余恒 `ask`、`FILE_WORKDIR` 路径受限）。加新工具只需实现 `tools.base.Tool` 并在 `tools/builtin/__init__.py::build_default_tools()` 里 `registry.add(…)`——**不要**在别处写 `if name == "…"` 分支，registry 是唯一分发点。
- **工具安全**：每次工具调用都先经过一道统一的执行边界——`allow`/`ask`/`deny` 策略（只读内置中 `get_current_time` / `echo` 默认 `allow` 不打扰；`system_info` 虽同样只读，但当前刻意设为 `ask` 以便演示审批流程；未来新工具默认 `ask`）→ 参数的 JSON Schema 校验（`jsonschema`，非法/错类型/多余字段直接拒绝、不执行）→ 需要时的一次性 Telegram 人工审批（`Approve`/`Deny` 按钮，按「发起者 + 原会话」绑定、会过期、只能点一次）→ `asyncio.wait_for` 单工具超时 → **只记元数据**的 append-only 审计（`tool_audit_events` 表，只存 `scope_hash` + 工具名 + 事件 + 结果码 + 耗时）。审计可用 `/tool_audit [limit]` 查看（只显示工具名/事件/结果码/耗时，绝不显示参数或结果）。策略/审批/审计**不记录、不显示**任何参数、结果、异常正文、图片、密钥或你的原始 user id。详见 [工具与工具安全](tools.md)。
- **远程 MCP 工具（Streamable HTTP + stdio）**：`mcp/` 包在**启动时**连到运维配置的 MCP 服务器——**远程 Streamable HTTP** 端点，或**本地 stdio 进程**（由后端 spawn 一个子进程、走其 stdin/stdout，`command`/`args`/`env`/`cwd` 均**不**经 shell，`args` 原样传递）——`tools/list` 发现工具后把每个包装成一个标准 `Tool`（`mcp_<server>__<remote>` 命名、默认 `ask`），注册进**同一个** registry。也就是说 MCP 只是又一个 **Tool Provider**：它**完全复用 Phase 3 的执行边界**（策略 → JSON Schema 校验 → 需要时的一次性审批 → 单工具超时 → 审计），没有第二条执行路径。每个服务器**故障隔离**（一个宕机——stdio 的 spawn 失败也算——不影响其余与内置工具）、**原子发现**（该服务器任一工具名/schema 非法或重名 → 整台不注册）。http 端点/bearer token 与 stdio 的 `command`/`args`/`env`/`cwd` **只来自严格启动配置**（token 是**环境变量名**，值 env-only、绝不入库/日志）；调用失败回稳定、**不回显**的码（`mcp_unavailable`/`mcp_tool_error`/`mcp_unsupported_result`/`mcp_result_too_large`）。`/mcp_status` 只读显示各服务器 up/工具数，**不**发起连接/刷新/LLM/MCP 调用。详见 [远程 MCP 工具](mcp.md)。
- **MCP 用户级 OAuth（phase 4.x）**：给 MCP 服务器配上 `"authentication": {"type":"oauth","provider":"google"}` 后，`/mcp auth <server>` 为**你的 Telegram 账号**发起标准 authorization-code 登录（`state` 单次使用 + TTL、内联按钮返回登录 URL、回调 `GET <OAUTH_CALLBACK_BASE_URL>/oauth/callback` 由一个最小 HTTP 服务器在 PTB 同一事件循环里处理）。凭据按 `(telegram_user_id, provider, mcp_server)` **每用户每服务器一条**落库（`oauth_credentials`），重新登录 upsert；**`/new`、`/start`、重启都不影响登录状态**；跨用户隔离（别人的凭据不可见）。工具执行时 access token 自动取用/刷新（轮换则持久化新 refresh token，未轮换保留旧的；**刷新失败不删凭据**），由工具 loop 经 contextvar 把当前 principal 传给 `httpx2.Auth` 钩子完成——**不**改动 LLM client / service / 审批 / 审计语义。`/mcp` 显示你本人的 OAuth 状态，`/mcp auth` 发起登录。provider 抽象（`mcp/auth/provider.py`）下 `main.py` 是唯一按 provider 名分派处；access/refresh token、authorization code、client secret **永不**进日志/命令/异常文案。详见 [远程 MCP 工具](mcp.md)。
- **只读基础设施观测（SSH，phase 5.1）**：`infrastructure/` 包是又一个 **Tool Provider**（与 MCP 同类）。对每个运维配置的 SSH 目标（目标须为 Linux + systemd；目标列表来自内联 `INFRA_SSH_TARGETS`，或默认文件 `config/infra_ssh_targets.json`，或 `INFRA_SSH_TARGETS_FILE` 指向的文件——后者优先），产出**三个固定、无参、只读**工具——`infra_<target>__host_status` / `__disk_status` / `__service_status`（主机 / 已配置挂载点磁盘 / 已配置 systemd 服务 状态），注册进**同一个** registry，因此**完全复用 Phase 3 的执行边界**（策略 → JSON Schema 校验 → fail-closed 预审计 → 需要时的一次性审批 → 单工具超时 → 审计），没有第二条执行路径。三个工具**默认 `allow`、严格只读**：因命令固定、无参、走主机密钥固定的仅密钥连接，与 `get_current_time` / `echo` 一样**无需每次审批**（审批步被跳过；主人仍可把一个 pin 成 `deny`）；模型**无法**指任何 host / path / service / command——工具无参，远程命令是**代码常量**（模板），唯一插值的是启动期已严格校验并 shell 引号转义的 `mounts` / `services`。每个被调用的工具开一条**主机密钥固定**（`known_hosts` 显式文件）、**仅密钥**（`client_keys`、SSH agent 关闭、密码/键盘交互关闭）的短命 AsyncSSH 连接、命令跑完即关闭；无持久连接、无自动重连。stdout 走严格解析器，任何失败（连接/认证/主机密钥/非零退出/stderr/畸形/超大）都映射到稳定、**不回显**的码（`infra_unavailable`/`infra_invalid_response`/`infra_result_too_large`）。`asyncssh` **惰性导入**（仅在被调用的工具真要连接时）；启动只校验本地配置/密钥文件存在、**不触网**。`/infra_status` 只读显示**已配置**的目标名 + 其三个工具名 + 总数（read-only），**不**连接、**不**探活、**不**调 LLM，且明确不显示可达性结论；host/port/用户名/key 路径/known_hosts 路径/mount/service/command **绝不**进其输出、日志或审计。详见 [工具与工具安全](tools.md)。
- **可选的 `exec` shell 工具（默认关闭）**：`ENABLE_EXEC_TOOL=true` 才注册 `exec`（`/bin/sh -c <command>` 完整 shell，支持管道/重定向/`&&`），返回 `{exit_code, stdout, stderr}`。它是**通用性最强**的状态变更本地能力（任意 shell 工作），因此**恒 `ask`**——每次调用都需一次性人工审批，且**完整命令逐字**显示在审批卡的 `Action:` 块里（`exec` 覆写 `approval_detail` 钩子，把命令以 bash 命令块呈现，替换默认的 `Arguments:` JSON；模型无法自批）。审批之上还有一层**静态灾难性命令 denylist 兜底**（`tools/exec_policy.py`：递归 `rm` `/`/`$HOME`、`--no-preserve-root`、fork bomb、`curl|sh`、`dd`/`mkfs`/裸写块设备、`shutdown`/`reboot`/`halt`/`init 0/6`、`chmod 777 /`），在 **spawn 之前**拦截——**即便你刚点了批准**也生效（防审批疲劳误批）。它是**兜底不是沙箱**（无法理解意图，故意小而保守）。子进程用**参数向量** spawn（绝不 `shell=True`）、`start_new_session` 进程组化，超时/取消时**整棵子进程组被 `SIGKILL`**（不留孤儿）。stdout/stderr 各自**尾截断**到 `MAX_EXEC_TOOL_RESULT_CHARS`（超限加 `[N chars … truncated]` 标记，**不是**报错）。非零退出码**也算成功运行**（以 JSON 返回供模型判断）。命令与 stdout/stderr **永不进日志、永不进审计表**。`EXEC_WORKDIR` 可固定运行目录。**无沙箱 / 无降权 / 无 cgroup / seccomp**——一条被批准命令的爆炸半径 = bot 运行账号（建议**不以 root 运行**）。详见 [工具与工具安全](tools.md)。
- **可选的 `file` 文件工具集（默认关闭）**：`ENABLE_FILE_TOOL=true` 才注册九个 `file_*` 工具，是第二个状态变更本地能力——比 `exec` **更窄**、更可控：模型无需拼 shell 就能读文件、精确改文件、移动/复制/新建/删除。九个工具全部限定在 `FILE_WORKDIR` 内：`file_read`（`allow`，读 UTF-8 文本、尾截断）/ `file_ls`（`allow`，列目录、截断到 `MAX_FILE_LIST_ENTRIES`）/ `file_edit`（`ask`，把**唯一** `old_string` 换成 `new_string`，`replace_all` 可全部）/ `file_mv`（`ask`，移动/重命名，不覆盖）/ `file_cp`（`ask`，复制文件或目录树，不覆盖）/ `file_rm`（`ask`，仅删**普通文件**）/ `file_mkdir`（`ask`，新建目录，`parents` 可建中间层）/ `file_rmdir`（`ask`，仅删**空目录**）/ `file_touch`（`ask`，新建空文件/更新 mtime）。`file_read` / `file_ls` 只读、声明 `allow`（免审批）；**其余七个恒 `ask`**（每次调用一次性人工审批，模型无法自批）——`file_edit` 覆写 `approval_detail` 钩子，把替换以 **git diff 风格**（`--- a/<path>` / `+++ b/<path>` 头 + 逐行 `-`/`+`）呈现在 `Action:` 块里、标注 `diff` 语言供语法高亮。核心安全机制是**路径受限**：所有 `path` / `source` / `target`（含 `..` 与**符号链接**）须解析在 `FILE_WORKDIR` 内，否则**在任何 I/O 之前**被拒（`file_path_escape`）——**即便你刚点了批准**也读不写不出，因此 `FILE_WORKDIR` 启用时**必填**（须为已存在目录）。**窄动词、不覆盖**（`file_rm` 不删目录、`file_rmdir` 只删空目录、`file_mv` / `file_cp` 目标已存在则拒）。写入用**原子写**（同目录 temp + `fsync` + `os.replace`）；`file_read` 内容尾截断到 `MAX_FILE_READ_CHARS`，`file_edit` 的 `old_string`/`new_string` 受 `MAX_FILE_STRING_CHARS` 约束（同时烧进 schema `maxLength`）。路径、文件内容、old/new 串**永不进日志、永不进审计表**。有意**不做**整文件写入/追加/删除一整棵树/覆盖式移动复制/任意 shell（这些更激进的操作交给 `exec`）。详见 [工具与工具安全](tools.md)。
- **图片输入 + 持久化**：Telegram 照片（可带说明文字）经 `telegram/media.py` 规范化为渠道无关的 `AgentMessage`，图片 base64 内联交给模型；收到的图片以内容寻址 blob 落盘并在后续历史里重新入窗（见 [数据库](database.md) `attachments` 表）。详见 [多模态与附件](multimodal.md)。
- **上下文预算管理**：除了按 `MAX_CONTEXT_MESSAGES` 计消息数，还有一道**模型无关的估算 token 预算**（`MAX_CONTEXT_ESTIMATED_TOKENS`）。每次请求前按「完整历史 turn、从新到旧」选取历史，使请求同时满足消息数与估算预算；某个历史 turn 的图片放不进去时，该 turn 降级为纯文本（其图片**不读取、不发送**），而不跳过去挑更旧的内容。当前请求本身永远保留、其图片不降级；若仅 system + 当前请求就已超预算，则不调用 LLM，回一条「请缩短文字或减少图片」的安全提示。详见 [上下文管理](context-management.md)。
- **显式长期记忆**：`/remember` 显式保存的记忆存在 `memories` 表，按 `scope`（账号）隔离，**跨 `/new` 与重启保留**。普通文字消息到达时，`memory/` 包用**纯词法**（小写化 + CJK 单字/ASCII 词元 + 子串命中优先 + 词元重叠计数，纯 Python，无 embedding/向量库/FTS5）在**该账号自己的记忆**里确定性地排序；命中的记忆作为**一条**独立的参考消息（`user` 角色，固定 wrapper + `- [memory #id] 原文`）插在主 system prompt 之后、历史之前——**不**用第二条 system 消息（很多 OpenAI 兼容端点会对「两条 system 消息」直接 400），且其估算成本计入 `MAX_MEMORY_ESTIMATED_TOKENS` 子预算（超则跳过、不截断）。只有**真正被注入**的记忆会更新 `last_retrieved_at`。详见 [长期记忆](memory.md)。
- **定时任务（cron，phase 9）**：在启动配置里声明一个 cron 定时任务后，后端到一个后台调度循环（单 `asyncio.Task`）到点**自动**跑一次 Agent——**不需要**任何人发消息触发。每个任务在**专属、全新**的会话里执行（保留区间的合成 `telegram_chat_id`、每次 `reset_conversation` 从零开始、运行后 `delete_conversation` 删除、不留痕；被杀的运行靠 `reset_conversation` 自愈 + 启动清扫兜底），**不**并入你日常会话、**不**跨运行累积上下文，因此**不**消耗你绑定聊天的上下文预算。它**完整复用** `process_message` 的既有执行路径（工具 gate / 审计 / 上下文 / 记忆 / 持久化），没有第二条执行路径——prompt 触发 `ask` 工具时，审批卡会经 `delivery_chat_id` 路由到**你绑定的聊天**（而非那个一次性专属会话），批准才执行。跑完向 `chat_id` 发一条**格式化通知**（任务名 + 完整结果）；失败发一条固定、安全、**不回显** prompt 的短通知。cron 是**严格 5 字段**纯 Python 实现（`0`/`7` 都是周日、dom+dow 是 Vixie **OR** 语义、日历不可能的表达式返回 `None` 而非死循环）；时区由 `SCHEDULE_TIMEZONE` 决定（不设则用进程本地时区）。**不 catch-up**（停机期间错过的触发点不回放，重启从当前时刻重算下次触发）、每任务**单飞**（上一次还在跑则跳过新 tick）、故障隔离（一个任务失败不影响其余与循环）。**定时任务只来自启动配置**（改需重启；模型/聊天/工具参数无法创建、修改或删除），纯出向、**不**暴露任何新端口。`/schedule_status` 只读显示各任务的**名字 + cron + 下次触发时间**（**不**显示 prompt/chat_id），**不**触发任何运行、**不**调 LLM。详见 [定时任务](scheduling.md)。
- **流式回复（Bot API 10.0 `sendMessageDraft`，默认开）**：`ENABLE_STREAMING=true` 时，**私聊**会在输入框显示一个**实时草稿预览**（`_DraftStreamer` 经 PTB 原生 `send_message_draft`），随模型生成逐词更新，**同时**保留「正在输入…」作为兜底（草稿能显示时草稿为主；草稿被拒时 typing 仍在，用户始终能看到「bot 在工作」）；草稿按 0.3 s 节流、只推**尾段**（上限 `CHUNK_SIZE`）。**群组 / 频道**与 `ENABLE_STREAMING=false` **始终降级**为原有「正在输入…」+ 分块最终回复。草稿是**临时预览**（约 30 s 无更新即过期），**完整回复始终照常作为普通消息发出**——即便你的 bot 尚未被 Telegram 加入流式白名单（`send_message_draft` 会被拒），也只是草稿静默失败（只记录错误类别、**绝不**记录回复正文，typing 照常兜底），最终消息照常送达，**无损**。流式是**渠道无关**的：`on_text_delta` 回调从 `llm/client.py` → `agent/tool_loop.py` → `agent/service.py` 逐层下传（只转发、不解析），Telegram 层是唯一决定「何时流式」之处；`process_message -> str` 的返回形态与 `AgentService` 的渠道无关性都不变。**停止**中途生成仍用 `/stop`。
- **降级开关**：`ENABLE_TOOLS=false` 时完全退回纯对话（不传 tools、不做工具相关持久化）；图片处理与工具开关相互独立（**定时运行在 tools 关闭时仍工作**，只走单次 completion）；`ENABLE_STREAMING=false` 时所有聊天退回「正在输入…」+ 分块回复。

**有意不做 / 限制**
- **本地默认仅 3 个只读工具**（`get_current_time` / `echo` / `system_info`）+ **只读 SSH 观测（phase 5.1）** 的固定 host / disk / service 三个无参工具。默认部署**仍零子进程、无 shell 执行、无文件写入**（"by design, no subprocess" 对默认部署依然成立）；仅有的两个状态变更本地能力都是**默认关闭**的可选能力：`exec`（`ENABLE_EXEC_TOOL=true` 才开启，恒 `ask`、静态 denylist 兜底、进程组杀、输出尾截断，命令与 stdout/stderr 永不入日志/审计表——见上）与 `file` 工具集（`ENABLE_FILE_TOOL=true` 才开启，九个 `file_*` 工具——`file_read` / `file_ls` 只读 `allow`、其余恒 `ask`，`FILE_WORKDIR` 路径受限、窄动词不覆盖、原子写，路径/文件内容/old/new 串永不入日志/审计表——见上）。除此之外无联网扫描、Docker 等状态变更工具（`exec` 可跑任意 shell、`file` 工具集只做 `FILE_WORKDIR` 内的受限文件/目录操作）。每次调用仍都经过统一的执行边界（策略 / JSON Schema 校验 / 需要时的一次性审批 / 单工具超时 / 只记元数据的审计，见「能做的」与 [工具与工具安全](tools.md)）。工具调用的**完整 transcript 仍不落库**（不落 `tool_calls`/`tool` 消息，无法逐条回放），但**元数据审计**可用 `/tool_audit` 事后查看。
- **图片仅本地磁盘、仅照片**：blob 只落 `ATTACHMENT_STORAGE_PATH`，无配额/后台 GC/单附件删除（`/new` 是唯一回收点）；文档/贴纸/视频/音频仍被丢弃（`ContentPart` 已为它们预留）。
- **估算而非精确 token**：`MAX_CONTEXT_ESTIMATED_TOKENS` / `MAX_MEMORY_ESTIMATED_TOKENS` 是保守、确定、模型无关的**估算**，用于相对选择与保护，不等于 provider 的计费 token；若实际 endpoint 仍报上下文超长，会走既有的安全 `http_error` 提示，本阶段不做重试或自动探测模型窗口。
- **记忆是显式 + 词法检索**：记忆**只**由用户用 `/remember` 显式保存，**不**自动从对话里抽取/摘要；检索是纯词法（子串命中 + 词元重叠），**没有**语义/embedding/向量库/FTS5，对同义改写、近义换词的召回有限；一条记忆是整条注入或整条跳过，不逐句裁剪。**跨语言召回尤其弱**：词元只在同一语言的词元空间内比对，用英文保存的记忆（如 `My name is FibreCase.`）用中文问（如「我的名字是什么」）时，中文 query 的词元与英文记忆的词元零重叠，因此**不会被检索注入**、模型也就答不出；反过来用英文问则能命中（且常是靠 `is`/`my`/`name` 这类表层词元碰撞，而非记忆里的专名）。**规避方式**：为你常用的每种语言各存一条记忆（例如再发 `/remember 我的名字是 FibreCase。`），中文问法即可命中。真正的跨语言/语义召回需要 embedding 或外部检索服务，超出本阶段「无外部依赖」的约束，留待后续。
- **MCP 两种传输（远程 Streamable HTTP + 本地 stdio）**：http 连远程端点；stdio 由后端 spawn 一个**运维配置的**子进程并走其 stdin/stdout（子进程由 SDK 收尾；**不**经 shell）。**不**自动重连（http 会话或 stdio 进程中途断开 → 该次调用回 `mcp_unavailable`，下次进程启动才重新发现）、**不**支持 resources/prompts/sampling，只取**文本**结果（非文本/空/超大/异常一律回稳定码，不回显）。工具结果受 `MAX_MCP_TOOL_RESULT_CHARS` 硬上限约束。http 的端点/头/token、stdio 的 `command`/`args`/`env`/`cwd`、工具结果、异常正文、服务器 instructions **绝不**进日志、审计或 `/mcp_status`。OAuth 仅限 **http** 传输、**用户级**（stdio 无请求可带头，凭据放其 `env`；见「能做的」），不支持群组/共享/多账号切换。详见 [远程 MCP 工具](mcp.md)。
- **未涉及**：Docker/Pi、Web search/RAG、向量库、Redis/PostgreSQL、Web 前端、**群组/共享级 OAuth 与多账号切换**（用户级 OAuth 已支持，见上）、多 Agent、autonomous loop、记忆自动摘要/抽取、语音/TTS/STT。
- **定时任务的刻意限制**：定时任务**只**来自启动配置（改需重启，无运行时管理命令 `/schedule add|rm|toggle`）；**每次运行全新会话**、任务间**无上下文连续性**（无法引用上次运行的结果）；**不 catch-up**（停机期间错过的触发点不回放）；**不**并入用户日常会话、**不**投递附件/图片（只发文本）；定时运行**不进 `/stop`**（它不进交互 handler 的 `_IN_FLIGHT` 槽位，受其专属会话的 per-conversation lock 与工具超时自然收敛）；`/schedule_status` 与日志/审计**绝不**泄漏 prompt / 回复 / chat_id / user_id / cron。详见 [定时任务](scheduling.md)。
